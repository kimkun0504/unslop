# Known limits

What unslop does not yet guarantee, so nothing here is mistaken for a promise.

| Area | Limit | Mitigation |
|---|---|---|
| macOS | The hooks, the installer, the contract check and the Python template run on macOS with its stock bash 3.2 and BSD tools in CI. The other templates are tested only on Linux. | Run `bash tests/hooks/run.sh` and `bash tests/install/run.sh` on your Mac after cloning; both should end with `0 failed`. |
| Sandbox and ruleset | Configuration rather than code, so nothing here tests them. | Run `/sandbox` in Claude Code, and try a direct push to `main` once the ruleset is applied. |
| Shell command guard | Matches text. A command hidden in a variable (`G=git; $G push --force`) gets past it. | The sandbox, the missing credentials and the ruleset are the real boundary; the guard catches ordinary mistakes. |
| Read tool | Deny rules on the Read tool match paths, not file contents opened by scripts. | Shell scripts run sandboxed with `denyRead` on credential folders. |
| Kotlin | detekt 1.23 bundles an older Kotlin compiler, so its type-aware rules do nothing on Kotlin 2.4. | The Kotlin guard bans `println`, `print`, `TODO` and `!!` by parsing. Move to detekt 2 when it is stable. |
| Kotlin mutation | PIT skips calls into `kotlin.jvm.internal`, the null checks the compiler inserts, which no test can observe. | None needed; the remaining mutants are all killed. |
| Go mutation | The Go mutation tools are unmaintained, so the Go template has no mutation gate. | Native fuzzing, the race detector and 100% coverage. |
| .NET mutation | Stryker.NET's Microsoft Testing Platform runner is marked preview. Stryker 4 silently tested nothing under this platform and still exited 0. | `scripts/mutation` passes only when Stryker reports a final score of 100%, and lists every surviving mutant otherwise. |
| Ruby mutation | mutant is free only for open source. The template sets `usage: opensource` in `.mutant.yml`. | A commercial project buys a mutant licence and sets `usage: commercial`, or removes `scripts/mutation` and says so in its README. |
| Elixir mutation | No maintained mutation testing tool exists for Elixir, so the template has no `scripts/mutation`. Property tests with StreamData and 100% line coverage carry more of the weight. | Add one when the ecosystem has it. |
| Elixir coverage | Erlang's cover tool measures lines, not branches. | Keep functions small and use multi-clause functions, so each branch is its own line. |
| Swift mutation and dead code | Muter, the Swift mutation tool, does not support Linux, and Periphery needs an index store build the template does not run, so the template has neither. | Run Muter on a Mac if you need it; review unused code by hand. |
| Swift toolchain in CI | `setup-swift` lists versions only up to 6.2, so CI runs in the official `swift:6.4.2-noble` container, pinned by tag rather than digest. | Pin the image digest once you can read it from Docker Hub. |
| Ruby and Elixir supply chain | Bundler and Hex have no minimum release age, unlike the uv and pnpm templates. | The lockfile is installed in frozen mode and `bundle-audit` runs in CI; Renovate can add a release-age delay. |
| Terraform mutation | No maintained mutation tool exists for Terraform. | Every secure default and input validation is asserted in `terraform test`, and checkov scans the plan. |
| Where templates were built | Python, TypeScript, Go and Rust were built and tested locally and in CI. Kotlin, Java, Terraform, .NET, PHP, Ruby, Elixir and Swift could only be built in CI, because their package registries are blocked in the build session. | Every template is proven the same way in CI: scaffold, verify, mutation and planted violations. |
| Cloud sessions | Claude Code on the web never reads the machine layer. The plugin and the repository's permission rules are meant to come with the clone, but sessions whose project root is not the repository skip them silently. | CI and the ruleset still apply to every pull request. |
| `allowManagedHooksOnly` | Left off, because turning it on disables `/goal`. A project could add its own hooks. | Project hooks cannot remove the managed hooks, which always run. |
| Adopted repositories | Architecture rules, mutation testing and dead-code checks are not adopted, because they depend on a layout the repository may not have. detekt runs without type resolution, so its type-aware rules are inactive; the Kotlin guard covers `println`, `TODO` and `!!`. | Add architecture rules per repository once the layers exist, or move the code into a template project. |
| Adopted formatting | .NET and PHP have no formatter that reads standard input, so their profiles leave formatting to the project. Swift formatting runs only when the repository has a `.swift-format`, so a project's own style is never replaced by swift-format's defaults. | Keep the project's formatter in its own CI step. |
| Adopted Python types | Adopted Python repositories use basedpyright's strict mode, not the templates' `all` mode, because `all` reports every use of an untyped legacy function as a new finding. Real defects such as optional member access and wrong return types are still caught. | Move to `all` once the legacy boundary is typed. |
| Adopted lint style | Ruby, Swift and the JVM profiles add defect-focused rules on top of the project's own configuration rather than the templates' house style, so new code matches the code around it. RuboCop's magic-comment and documentation-comment cops are off, because they contradict decision 0001. | Tighten the project's own configuration over time. |
| Adopted Swift warnings | Compiler warnings come from an incremental build, so a file that is not rebuilt reports none of its old warnings. New warnings in changed files are always caught. | Run `unslop baseline` after a clean build if the reported counts drift. |
| Adopted Elixir and PHP tools | Credo is ratcheted only when the project already depends on it. PHP coverage needs the pcov or Xdebug extension. | Add Credo to the project, and enable pcov in CI as the generated workflow does. |
| Adopted coverage | Changed lines in files the coverage tool does not measure, such as code outside the configured source folder, are not checked. | Keep new code inside the measured source folders, or widen them with a `tests` override in `unslop.toml`. |
| Adopted baselines | Counts are per file and rule, so renaming a file with findings makes them look new. A file that is deleted and recreated loses its allowance. | A human runs `unslop baseline` in the pull request that renames the file and adds the `unslop-reviewed` label. |
| Large repositories | `unslop check` lints the whole repository and runs every test. `unslop init` measures the run and sets the end-of-turn budget to twice that plus a minute, up to 1700 seconds. A slow check still means slow feedback for Claude. | Override `tests` in `unslop.toml` with a fast subset; CI runs the same command, so keep the full suite in another CI job. A human can change `fast_check_seconds`. |
| Worktrees | In a worktree under `.claude/worktrees/`, the protected files and the end-of-turn check apply to that worktree when it contains `unslop.toml`. A subagent working in its own worktree is not gated when it finishes; its changes are checked when the main session stops, if they were merged back, and in CI. | Let CI and the ruleset gate the branch the worktree pushes. |
| Plugin `bin/` folder | The plugin puts `unslop` on Claude's PATH through its `bin/` folder. claude.ai and Cowork refuse to install plugins with a `bin/` folder, so the plugin is for Claude Code only. | Use Claude Code; other surfaces rely on CI. |
| Plugin activation | The plugin turns on only after someone opens the repository in Claude Code and accepts the folder trust prompt, and each person can disable it for themselves with `/plugin`. | Install the machine layer to run the same hooks from managed settings, where they cannot be switched off, and rely on CI for everyone else. |
| Distribution | unslop installs from a git tag (`uvx --from git+https://github.com/kimkun0504/unslop@v0.3.2`) until it is published to PyPI. The first run of each version clones the repository, so it needs network access to GitHub. | See [Releasing](releasing.md) for publishing to PyPI. |
| Stacks in the same folder | Each stack needs its own folder, and `unslop init` only looks at the root and the top-level folders. A Python and a TypeScript project sharing the root, or a stack two folders down, has to be listed by hand. | Pass `--stack PROFILE:FOLDER` for each stack. |
| Planned standards | Several standards in [standards.md](standards.md) are marked Planned: API contract linting, migration linting in a database template, OpenTelemetry, container and IaC templates, Web Vitals budgets. | Each will land as a template or gate with its own CI proof. |
